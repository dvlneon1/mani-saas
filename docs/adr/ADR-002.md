# ADR-002: Expo SDK 58 vs React Native CLI

**Status:** Aceito
**Data:** 2026-11-02

## Contexto

O app mobile do Projeto Mani precisa rodar em Android e iOS com desenvolvimento rápido, over-the-air (OTA) updates e acesso a câmera/galeria (fotos antes/depois) e assinatura. A escolha está entre Expo (managed workflow, SDK 58) e React Native CLI (bare workflow).

## Decisão

Adotar **Expo SDK 58** com `expo-router` para navegação.

## Consequências

**Positivas:**
- Builds via EAS Build (cloud) sem manter Xcode/Android Studio locais no CI básico.
- Expo Updates para OTA (JS bundle) sem passar por revisão de loja em mudanças puramente de JS.
- `expo-router` fornece navegação baseada em arquivos (stack + tabs), alinhado ao Next.js App Router do web.
- Biblioteca NativeWind v4 com suporte oficial a Expo/RN.
- Módulos Expo (camera, image-picker, net-info, app-state) cohem com offline (ADR-005) e galeria.

**Negativas/Riscos:**
- Módulos nativos customizados precisam de `expo-dev-client` ou builds EAS customizados (plugins de config).
- Dependência do ecossistema Expo para versões do React Native (0.88 no SDK 58).

## Alternativas consideradas

**React Native CLI (bare):** Controle total de native modules, mas aumenta custo de manutenção do iOS/Android nativo e perde OTA simples do Expo. Rejeitado para MVP pelo time pequeno.
