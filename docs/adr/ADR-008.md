# ADR-008: Turborepo monorepo vs repos separados

**Status:** Aceito
**Data:** 2026-11-02

## Contexto

O Projeto Mani tem 5 pacotes com código compartilhado (tipos, schemas, design system). A decisão é entre um monorepo (Turborepo) e repositórios separados por pacote/app.

## Decisão

Adotar **Turborepo monorepo** com workspaces npm (`apps/*`, `packages/*`).

## Consequências

**Positivas:**
- Tipos e schemas compartilhados (`@mani/shared`, `@mani/design-system`) usados por mobile e web sem duplicação; alteração em um pacote reflete em todos dependentes.
- Build orchestrated pelo turbo: `build` depende de `^build`, garantindo ordem correta (shared → design-system → apps).
- Comandos unificados na raiz: `npm run build`, `npm run dev`, `npm run lint`, `npm run typecheck`.
- Versionamento único e atomicidade de mudanças que tocam múltiplos pacotes (ex: novo campo no banco → tipo no shared → consumo nos apps no mesmo PR).

**Negativas/Riscos:**
- Build de um pacote aciona rebuild de dependentes (mitigado por cache do turbo e outputs definidos).
- Um `package.json` quebrado na raiz afeta todos os pacotes; requer cuidado em dependências cruzadas.
- CI precisa rodar `turbo run build` (ou afetado) em vez de builds isolados.

## Alternativas consideradas

**Repositórios separados:** Isolamento de builds, mas compartilhamento de tipos exige publicação/versionamento de pacotes (`@mani/shared` no npm) — overhead alto para um time pequeno em fase inicial. Rejeitado.
