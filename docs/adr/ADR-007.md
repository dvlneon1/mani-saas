# ADR-007: Light-mode default vs dark brutalist

**Status:** Aceito
**Data:** 2026-11-02

## Contexto

O Design System do Mani definiu uma identidade visual com marca roxa (#8B5CF6) e tom clean. O conceito de UI inicial contemplava um dark mode brutalist, mas o público-alvo (manicures/estúdios de beleza) e os casos de uso (fotos de unhas, agenda ao ar livre) pesam na decisão.

## Decisão

Adotar **light-mode como default**, com suporte a dark mode opcional (não brutalist) futuro.

## Consequências

**Positivas:**
- Legibilidade superior para agendamentos, listas de clientes e financeiro em uso diário.
- Fotos de antes/depois (unhas) ficam mais fiéis em fundo claro; core do valor do app.
- Menor complexidade no Design System NativeWind v4 (uma paleta principal definida em `tokens.json`).
- Alinha com a marca (roxo + slate sobre fundo #FAFAFA).

**Negativas/Riscos:**
- Usuários que preferem dark (uso noturno) terão opção limitada no v1; dark mode pode ser adicionado depois como tema alternativo sem quebrar componentes (NativeWind suporte a temas via classes condicionais).

## Alternativas consideradas

**Dark brutalist default:** Impactante visualmente, mas prejudica leitura de listas longas e fidelidade de fotos de unhas; nicho demais para o público-alvo. Rejeitado para v1, possível como tema opcional posteriormente.
