# ADR-005: MMKV offline-first + sync background

**Status:** Aceito
**Data:** 2026-11-02

## Contexto

O app mobile (nail designers em atendimento) pode ficar sem conexão (estúdios com Wi-Fi instável, visitas domiciliares sem dados). O usuário deve continuar criando agendamentos, anotando clientes e tirando fotos offline, sincronizando quando a conexão voltar.

## Decisão

Adotar **offline-first com fila de sync em MMKV** (`react-native-mmkv`) no mobile.

## Consequências

**Positivas:**
- MMKV é síncrono e rápido (ideal para cache de leitura e fila de operações pendentes).
- Fila de ações (create/update/delete) armazenada localmente com idempotency key e timestamp; reaplicada ao restaurar conexão (`expo-netInfo` + `AppState`).
- Leituras servem do cache MMKV offline; escritas entram na fila e são replicadas ao voltar online.
- Reconciliação por `updated_at` mais recente (servidor vence em conflito).
- Edge Function `/functions/v1/sync-offline` recebe a fila e aplica no banco com RLS do usuário.

**Negativas/Riscos:**
- Conflitos de edição simultânea exigem política clara (server timestamp vence; notificar usuário quando houver sobreposição).
- Fotos tiradas offline precisam de upload diferido (armazenar localmente, enviar quando online).
- Complexidade adicional no frontend (gerenciar estados online/offline, otimistic updates).

## Alternativas consideradas

**Online-only:** Simples, mas app inutilizável sem conexão — inaceitável para uso em campo. Rejeitado.

**SQLite local (expo-sqlite) + sync:** Mais poderoso para consultas complexas offline, mas API assíncrona e mais pesada que MMKV para o escopo atual (cache + fila). Rejeitado por simplicidade; pode ser reavaliado se o volume de dados locais crescer.
